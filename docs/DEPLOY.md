## ۱) گذاشتن روی گیت‌هاب

### راه اول — بدون خط فرمان (ساده‌ترین)

1. وارد <https://github.com/new> شو.
2. **Repository name**: `rozaneh` — **Private** یا Public (هر دو برای Railway کار می‌کند) — بدون README/LICENSE (چون خودمان داریم) → **Create repository**.
3. در صفحهٔ بعد روی **uploading an existing file** بزن.
4. فایل `rozaneh-v1.04.zip` را روی سیستم باز کن (Extract) و **محتوای پوشه** را — نه خود پوشه — داخل صفحه بکش و رها کن. باید این‌ها را ببینی: `app/`, `static/`, `docs/`, `Dockerfile`, `railway.toml`, `start.sh`, `requirements.txt`, `README.md` …
   - اگر پوشهٔ `data/` هم همراهش بود مشکلی نیست؛ دیتابیس دمو با اولین اجرا خودش ساخته/به‌روز می‌شود.
5. پایین صفحه **Commit changes**.

> ⚠️ هرگز فایل `.env` واقعی یا توکن ربات را کامیت نکن. روزنه همهٔ توکن‌ها را داخل دیتابیس (`/data`) نگه می‌دارد، نه در کد.

### راه دوم — با Git (برای به‌روزرسانی‌های بعدی بهتر است)

```bash
cd rozaneh                      # پوشهٔ پروژه
git init                        # اگر مخزن نیست
git add -A
git commit -m "Rozaneh v1.04"
git branch -M main
git remote add origin https://github.com/USER/rozaneh.git     # USER را عوض کن
git push -u origin main
git tag v1.02 && git push --tags
```

اگر Git از تو رمز خواست، از **Personal Access Token** استفاده کن (GitHub → Settings → Developer settings → Personal access tokens → Fine-grained → دسترسی *Contents: Read and write* به همان مخزن) و آن را به‌جای رمز بچسبان.

**به‌روزرسانی بعدی:** فایل‌ها را تغییر بده، بعد

```bash
git add -A && git commit -m "v1.04: ..." && git push
```

## ۲) بالا آوردن روی Railway

1. <https://railway.app/new> → **Deploy from GitHub repo** → مخزن `rozaneh` را انتخاب کن → اگر اجازه خواست، دسترسی به همان مخزن را بده.
2. Railway خودش `Dockerfile` را می‌بیند و build می‌کند (۲ تا ۳ دقیقه). در تب **Deploy Logs** تا دیدن `Uvicorn running on http://0.0.0.0:…` صبر کن.
3. **دیسک دائمی (مهم!)** — بدون این، با هر deploy دیتابیس و تنظیماتت پاک می‌شود:
   - روی سرویس → تب **Variables/Data** → **Add Volume** (یا `⌘/Ctrl + K` → *Create Volume*)
   - **Mount path**: `/data` ← دقیقاً همین.
4. **متغیرها** (تب **Variables** → *Raw Editor* یا تک‌تک):

   | Key | Value | توضیح |
   | --- | --- | --- |
   | `DATA_DIR` | `/data` | همان مسیر دیسک |
   | `ADMIN_PASSWORD` | یک رمز قوی | رمز اولین ورود |
   | `DEFAULT_TZ` | `Asia/Tehran` | منطقهٔ زمانی زمان‌بندی |
   | `COOKIE_SECURE` | `1` | چون Railway روی HTTPS است |
   | `SCHEDULER_ENABLED` | `1` | اجرای خودکار قواعد |

5. تب **Settings → Networking → Generate Domain** → یک آدرس `https://rozaneh-production-xxxx.up.railway.app` می‌گیری.
6. آدرس را باز کن → صفحهٔ ورود → رمز `ADMIN_PASSWORD` → وارد پنل شو.
   - اولین کار: **تنظیمات → امنیت** → تغییر رمز.

> اگر Railway پورت خواست: هیچ کاری لازم نیست، `PORT` را خودش تزریق می‌کند و `railway.toml` هم `--port ${PORT}` را پاس می‌دهد.

## ۳) تست واقعی (به‌ترتیب انجام بده)

### ۳٫۱ سلامت سرویس

```bash
curl -s https://YOUR-DOMAIN/healthz
# {"ok":true,"app":"Rozaneh","version":"1.04"}
```
اگر این جواب آمد، سرویس زنده است. (Railway خودش هم `healthcheckPath = /healthz` را چک می‌کند.)

### ۳٫۲ اتصال کانال — با «بررسی اتصال»

در پنل → **کانال‌ها** → **افزودن کانال**:

| پیام‌رسان | آیدی کانال | توکن |
| --- | --- | --- |
| تلگرام | `-1001234567890` (آیدی عددی) یا `@mychannel` | از `@BotFather` |
| بله | آیدی عددی کانال | توکن ربات بله |
| ایتا | آیدی کانال **بدون** `@` | توکن از `eitaayar.ir` |
| روبیکا | شناسهٔ کانال (`c0…`) | توکن ربات روبیکا |

قبل از ذخیره، پایین فرم **قوانین و محدودیت‌های این پیام‌رسان** را نشان می‌دهد (سقف متن/کپشن، آپلود عکس، فاصلهٔ ایمن).

بعد از ذخیره، روی کارت کانال دکمهٔ **🛡 بررسی اتصال** را بزن:

- ✅ `اتصال تأیید شد — @my_bot → کانال خبری` یعنی توکن سالم است و ربات کانال را می‌بیند و **هیچ پیامی هم در کانال نرفت**.
- ❌ `اتصال برقرار نشد: getChat:chat not found` یعنی ربات هنوز عضو/ادمین کانال نیست.
- ❌ `getMe:http_401:Unauthorized` یعنی توکن غلط است.

### ۳٫۳ ارسال واقعی — با «تست»

دکمهٔ **📡 تست** یک پیام واقعی می‌فرستد:

```
✅ روزنه وصل شد.
این یک پیام آزمایشی است؛ سرخطهای واقعی طبق زمانبندی همینجا منتشر میشوند.
```

اگر این پیام در کانال دیده شد، مسیر ارسال (شامل عکس) سالم است. اگر نه، متن خطا عیناً در توست و در ستون وضعیت کارت کانال ذخیره می‌شود — جدول خطاها در بخش ۵.

### ۳٫۴ یک دور کامل بدون انتشار

**قواعد** → ساخت قاعده: منابع + موضوع + ساعت → دکمهٔ **اجرای آزمایشی**:

- گزارش می‌دهد چند خبر خوانده شد، چند تا در بازه بود، چند تا به موضوع خورد، چند تا **جدید** بود، چند تا ترجمه شد.
- پیش‌نمایش پیام هر خبر را نشان می‌دهد (همان متن و کپشنی که واقعاً می‌رود).

### ۳٫۵ انتشار یک‌باره

همان قاعده → **اجرا** (بدون dry-run) → **آرشیو** را ببین: هر آیتم با وضعیت «ارسال شد» و شناسهٔ پیام. اگر عکسی داشته، به‌صورت پیام عکس‌دار رفته است.

از این لحظه scheduler هر ۱۵ ثانیه ساعت‌ها را چک می‌کند و سر ساعت، خودش می‌فرستد.

## ۴) Docker و VPS (خلاصه)

```bash
# داکر
docker build -t rozaneh .
docker run -d --name rozaneh -p 8080:8080 -v rozaneh-data:/data \
  -e ADMIN_PASSWORD='یک-رمز-قوی' -e DEFAULT_TZ=Asia/Tehran rozaneh
```

```bash
# VPS اوبونتو/دبیان (یک دستور، سرویس systemd می‌سازد)
ROZANEH_REPO=https://github.com/USER/rozaneh.git \
  bash -c "$(curl -fsSL https://raw.githubusercontent.com/USER/rozaneh/main/start.sh)"
```

اگر پشت Nginx هستی، `COOKIE_SECURE=1` بگذار و `X-Forwarded-Proto` را پاس بده.

## ۵) خطاهای رایج و معنی‌شان

| پیام | معنی | راه‌حل |
| --- | --- | --- |
| `getMe:http_401:Unauthorized` | توکن ربات غلط/باطل است | توکن را از BotFather/پنل پیام‌رسان دوباره بگیر |
| `getChat:chat not found` | ربات کانال را نمی‌بیند | ربات را ادمین کانال کن (تلگرام: اجازهٔ *Post Messages*) |
| `not enough rights to send photos` | ادمین هست ولی اجازهٔ عکس ندارد | دسترسی ارسال مدیا را بده |
| `http_403:Forbidden: bot was blocked` | ربات بلاک شده | آنبلاک کن |
| `rate_limited:30` | محدودیت نرخ پلتفرم | روزنه خودش یک‌بار صبر می‌کند؛ اگر تکرار شد فاصلهٔ قاعده را بیشتر کن |
| `network_error:timeout` | سرویس پیام‌رسان از سرور تو در دسترس نیست | از سرور بیرونی (Railway) تست کن؛ بعضی دامنه‌ها از داخل ایران/خارج فیلترند |
| `rubika_upload_unavailable` | مرحلهٔ `requestSendFile` جواب نداد | توکن روبیکا و نوع فایل را چک کن؛ متن بدون عکس ارسال می‌شود |
| `webhook_url_invalid` | آدرس وب‌هوک با `https://` شروع نمی‌شود | آدرس کامل بده |

هیچ‌کدام از این‌ها «موفقیت قلابی» ثبت نمی‌کنند: وضعیت آیتم در آرشیو و لاگ‌ها همیشه همان چیزی است که پلتفرم جواب داده.

## ۶) پشتیبان و بازگردانی

- پنل → **مدیریت → خروجی JSON**: کل تنظیمات، منابع، موضوعات، کانال‌ها و قواعد (بدون توکن، مگر اینکه تیکش را بزنی).
- بازگردانی: همان فایل را در **مدیریت → بازگردانی** بده.
- پشتیبان کامل (با توکن‌ها و آرشیو): فایل `/data/rozaneh.db` را از دیسک Railway کپی کن.
